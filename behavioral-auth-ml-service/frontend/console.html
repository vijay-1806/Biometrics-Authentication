Developer Quickstart Guide

Integrate continuous keystroke behavioral biometrics into your web application or backend.

1. How BioAuth Behavioral Biometrics Works

BioAuth passively evaluates the unique rhythm and timing patterns of how a user types on their keyboard. It captures high-precision key hold duration (time a key is pressed down) and digraph flight latencies (transition time between consecutive keystrokes). These intervals are transformed into statistical feature vectors and scored against an individual IsolationForest Machine Learning Model trained specifically on that user's baseline.

Zero Plaintext / Passwords
The service scores timing vectors only. Plaintext passwords or sensitive inputs are never transmitted or stored.
Real-Time Scoring
Fast sub-5ms ML inference with confidence intervals, rolling average trust scores, and anomaly detection.
Automated Risk Protection
Flags credential sharing, impostors, bot automation, and session hijacking in real time.
2. Authentication & API Key

Use a project credential with the minimum permissions required. Keep production secrets on your server and send the key in the X-API-Key header:

HTTP Header
X-API-Key: bio_live_YOUR_WORKSPACE_KEY

Manage project keys in Credentials.

3. Universal Web Client SDK Integration (Recommended)

Integrate with any web application (React, Next.js, Vue, or static HTML) using our lightweight, zero-dependency client SDK script:

Step A: Add Script to Your HTML Page
HTML
<script defer src="http://localhost:8000/sdk.js"></script>
Step B: Initialize the SDK and Attach Listeners
JavaScript
const bio = new BioAuth({
  apiKey: "YOUR_WORKSPACE_KEY",           // Create a scoped credential in the Credentials page
  userId: "student_or_customer_id",       // Unique user identifier in your platform
  mode: "verify",                         // "verify" for continuous scoring, "enroll" for baseline training
  baseUrl: "http://localhost:8000",
  onViolation: (alert) => {
    console.warn("Biometric Security Alert:", alert);
    // Trigger step-up verification or flag suspicious activity
  }
});

// Attach keystroke listeners to any form, textarea, or text input
bio.attach(document.getElementById("target-input"));
4. Direct REST API (Server-to-Server or Custom Clients)

For native apps or server-to-server workflows, submit raw keystroke event streams directly to the /verify endpoint:

cURL
curl -X POST "http://localhost:8000/verify" \
  -H "X-API-Key: YOUR_WORKSPACE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "user_49201",
    "events": [
      {"key": "t", "type": "down", "t": 0.0},
      {"key": "t", "type": "up",   "t": 68.2},
      {"key": "h", "type": "down", "t": 120.4},
      {"key": "h", "type": "up",   "t": 195.1}
    ]
  }'
5. Understanding Decision Actions & Risk Levels
Action Trust Score Risk Level Recommended Application Handling
ALLOW 70 – 100 LOW Typing rhythm conforms to authentic baseline. Permit user action silently.
STEP_UP 45 – 69 MEDIUM Rhythm fluctuation or provisional profile. Challenge with 2FA / OTP or secondary check.
DENY 0 – 44 HIGH Statistically confirmed impostor rhythm. Lock session, revoke auth token, or log security event.

API Reference

Comprehensive documentation for all BioAuth BaaS HTTP endpoints.

POST /verify

Scores a live keystroke timing sample against a user's Isolation Forest behavioral profile.

Headers:
X-API-Key: YOUR_API_KEY
Content-Type: application/json
Request Body:
{
  "user_id": "string (required)",
  "events": [
    { "key": "string", "type": "down" | "up", "t": float }
  ]
}
POST /enroll

Registers an enrollment typing sample. When sufficient samples are collected (10 for provisional, 20 for full), the model is automatically fitted and cached in memory.

GET /users/{user_id}/status

Returns the user's current enrollment sample count, model status (collecting, provisional, full), and in-memory cache status.

GET /v1/system/health

Returns cluster health, in-memory model cache hit ratio, and active enterprise features.

Webhooks

Receive real-time BioAuth event notifications signed with HMAC-SHA256.

Endpoint Configuration

Events sent: biometric.deny, biometric.step_up, biometric.verification

All webhook payloads are cryptographically signed using HMAC-SHA256. Verify the signature using the header X-Bio-Signature.
HMAC-SHA256 Signature Verification Example
Node.js / Express
const crypto = require("crypto");

function verifyBioAuthWebhook(req, secret) {
  const signature = req.headers["x-bio-signature"];
  const computed = crypto.createHmac("sha256", secret)
                         .update(JSON.stringify(req.body))
                         .digest("hex");
  return crypto.timingSafeEqual(Buffer.from(signature), Buffer.from(computed));
}
